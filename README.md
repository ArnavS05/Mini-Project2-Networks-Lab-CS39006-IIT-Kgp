# README

Server concurrency:
Uses select() in one process to handle multiple clients.
Each client socket has a small state machine for current protocol step.
No threads or child processes are used.

Design choices:
- Server sends one greeting per connection and waits for mode selection.
- Mode timeout is used so dead connections are not kept forever.
- SMTP2 command order is checked strictly using explicit states.
- Recipients are validated when TO is received, not at delivery time.
- Subject is stored as "(no subject)" if empty.
- Dot-stuffing is handled when receiving and when sending multi-line data.
- Body size is tracked after destuffing to enforce the exact limit.
- A failed message body does not write partial files.
- Message files are plain text so they are easy to inspect.
- Date is generated by the server at final delivery.
- LIST output uses parsed headers from stored files.
- READ returns full message content as stored.
- DELETE removes file from disk and updates in-memory mailbox view.
- COUNT avoids full LIST overhead when only total count is needed.
- Authentication attempts are capped and connection is closed after limit.
- Unknown or out-of-sequence commands return explicit ERR responses.
- Logging is timestamped for connect, auth, mailbox actions, and disconnect.

Mailbox IDs:
- Each user mailbox has files like 1.txt, 2.txt, etc.
- Next ID is max existing ID + 1.
- Deleted IDs are not reused.
- Existing mailbox files are scanned at server startup.
- Non-numeric filenames are ignored for ID calculation.

Assumptions:
- Userfile has valid username password pairs.
- Username lookup is case-insensitive.
- SMTP2 order is enforced as specified.
- Body size limit is 65536 bytes after destuffing.
- If mailbox is empty for a particular user, next ID can be 1 onwards.
- The executables will be executed from the root directory (the one where this file is present).
- Mailbox folder already exists or can be created by server on startup.
